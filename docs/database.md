# Database Design

H2 is used in-memory with `MODE=PostgreSQL`. The schema is generated by Hibernate via `ddl-auto=create-drop` for assessment portability. In production, replace this with Flyway/Liquibase migrations against a durable database.

## Table notes

| Table | Purpose | Key constraints |
|---|---|---|
| `users` | Authentication and authorization | unique `email`, BCrypt hash, role enum |
| `products` | Catalog and inventory | unique `sku`, `stock_quantity >= 0`, soft delete via `active` |
| `carts` | One active cart per user | unique `user_id` |
| `cart_items` | Cart lines | unique (`cart_id`, `product_id`) |
| `orders` | Completed checkout headers | unique `order_number`, indexed by user + placed date |
| `order_items` | Immutable order line snapshots | stores SKU/name/price at purchase time |

## Important design decisions

- **Order item snapshots** store SKU, name and unit price so historical orders are not changed by later catalog edits.
- **Soft deletion** of products keeps old order references valid and avoids destructive deletes.
- **Money** uses `BigDecimal(12,2)`; never `double`.
- **Auditing** adds `created_at`/`updated_at`; `@Version` adds optimistic concurrency control.
- **Inventory invariant** is enforced in SQL by:
  ```sql
  UPDATE products
     SET stock_quantity = stock_quantity - :quantity
   WHERE id = :id
     AND active = true
     AND stock_quantity >= :quantity;
  ```
  This is atomic and safe under concurrent checkout requests.

## Suggested production indexes

```sql
CREATE INDEX idx_products_active_category ON products(active, category);
CREATE INDEX idx_products_name ON products(name);
CREATE INDEX idx_orders_user_placed ON orders(user_id, placed_at DESC);
CREATE INDEX idx_order_items_order ON order_items(order_id);
CREATE INDEX idx_cart_items_cart ON cart_items(cart_id);
```
